# 按流量计费的订阅探测

适用于大量独立会话、按 GB 收费的代理。节点数量保持不变；同一服务器的不同用户名仍是独立节点，出口 IP 不会相互代替。

## 启用

订阅 → 编辑 → **探测策略 → 按流量计费**，保存。创建订阅时也可选择。默认继承全局，升级不会自动切换任何现有订阅。

建议从以下设置开始：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| 活跃节点出口检测间隔 | `24h` | 最近使用过的节点才进行周期检测 |
| 近期使用窗口 | `24h` | 超过此时间未使用的节点停止后台检测 |
| 使用前出口信息最大年龄 | `24h` | 首次使用或信息过期时同步验证 |
| 每月探测预算 | `1000000000` 字节 | 1 GB，按 ¥3/GB 估算约 ¥3 |
| 严格预算 | 关闭 | 默认预算限制后台任务；开启后使用前验证、手动检测也受限 |

首次导入、重新启用不会全量检测。新节点在正常可路由集合之外等待验证。分配时最多尝试三个符合订阅标签约束的候选，每次请求最多因此产生三个验证；地区条件在取得真实出口信息后再次检查。首次使用会增加检测等待时间。付费探测最多同时执行 8 个，其中后台最多 2 个，给首次验证留出容量；等待并发槽最多 15 秒，超时返回错误而不无限排队。已绑定节点在使用前按有效期检查，不会因为业务请求成功就把出口验证时间延后。

独立延迟探测关闭。一次 Cloudflare trace 检测同时提供出口 IP、地区和 TLS 握手延迟。付费节点的手动“延迟探测”也使用此合并检测。禁用的付费节点不能通过手动操作绕过策略。

失败复测按 5 分钟、30 分钟、2 小时、12 小时退避，之后保持 12 小时。空闲节点不进行后台复测；再次使用仍遵守退避。手动检测可以越过退避，但严格预算仍然生效。业务健康反馈沿用平台的被动熔断规则，成功请求提供健康反馈，不能证明出口 IP 没变。

## 严格 IP 管理

平台编辑中可设置 **付费节点出口验证最大年龄**，默认 `0s` 表示继承订阅。设置 `1h` 会将该平台的使用前验证期限收紧到一小时。最终采用平台和订阅两者中更短的期限。

验证完成后仍要通过原有的地区、健康、IP 绑定和账号治理校验。若治理返回的 IP 与验证后的 IP 不同，本次请求失败，不使用过期 IP 放行。

检查频率不是上游会话保持时间，不能保证检测之后供应商不会换 IP。缩短验证期限会增加必要验证流量。节点详情和平台账号绑定表显示出口 IP 上次验证时间。绑定 IP 已与节点当前 IP 不同时不显示验证时间，避免误导。

## 预算及统计

订阅编辑页展示今日、本月用量，按使用前验证、周期检测、故障复测、手动检测分别汇总次数、失败数和双向字节。日期和预算周期采用 UTC。费用显示按 ¥3/GB 估算。

- 计数位置在节点出站流之上，包含目标 TLS 交互，不包含所有代理协议外层或供应商计费附加量，因此不是供应商账单。
- 所有原因的用量计入月账本。非严格模式达到预算时只暂停后台检测，使用前验证和手动检测仍可继续并超过预算。
- 严格模式达到预算后需要重新验证的代理请求返回 `503 / PROBE_BUDGET_EXHAUSTED`；验证仍有效的现有路由可继续使用。
- 每次网络探测预留 64 KiB，完成后按实际字节结算。不足一个预留额度就暂停，最多会留下不足 64 KiB 的未使用预算。
- 网络读取/写入分别限制为预留额度的 3/4 和 1/4，合计不超过 64 KiB；正文另限 16 KiB；付费 trace 检测不跟随重定向。
- 异常退出后未结算的预留不会释放，保守占用当月预算，下一 UTC 月重新计费。普通重启不会清空已用额度或失败退避。
- 预算不足的后台重试最多缓存一分钟，避免几千节点不断查询数据库；调整预算值立即失效此缓存。
- 同一节点若属于多个启用订阅，只要有付费策略就不进入全局探测。按订阅 ID 排序后，第一个启用的付费订阅提供策略并承担一次计费，避免重复计数。对共享节点请保持付费策略一致。

以 5,000 个节点每天各做一次出口检测、单次 4–8 KB 为例，常规检测约 20–40 MB/天，约 ¥1.8–3.6/月。实际还包括首次验证、失败复测和手动检测；平台的更短期限也会增加用量。预算优先于这一估算。

## API

创建或 PATCH `/api/v1/subscriptions/{id}` 时，`probe_policy` 是完整替换的对象：

```json
{
  "probe_policy": {
    "mode": "metered",
    "egress_interval": "24h",
    "active_window": "24h",
    "max_egress_age": "24h",
    "monthly_budget_bytes": 1000000000,
    "strict_budget": false
  }
}
```

三个间隔最小为 `30s`。切回全局使用 `{"probe_policy":{"mode":"inherit"}}`。订阅响应增加 `probe_policy`、当月每日分类 `probe_usage`；统计读取失败时返回 `probe_usage_error`，不能将此状态解释为零流量。

平台创建/PATCH 增加 `egress_verification_max_age`，接受 `0s` 或至少 `30s` 的时长字符串。

## 持久化及发布

state.db 的第 10 版迁移新增订阅策略 JSON、平台验证期限、探测日账本和节点探测状态。迁移保留旧配置并默认为继承全局。部署前按原有流程备份 state.db 和 cache.db；不要直接修改线上数据库启用策略。

本功能不自动部署、不自动修改现有订阅。上线后先在目标付费订阅启用，观察完整的供应商统计窗口，对比两个探测域名与新账本。迁移后的数据库不要直接交给旧版本运行；需要回滚时使用升级前的备份。

## 探测日志

导航中的「探测日志」(`/probe-logs`) 展示 Resin 实际发起的出口和延迟检测，覆盖普通订阅与按流量计费订阅，不受业务请求日志开关影响。支持时间、订阅名称或 ID（包含匹配）、完整节点哈希、目标域名、类型、原因及结果筛选；除订阅外文本字段精确匹配。时间输入使用浏览器本地时区。

记录包括检测开始时间、订阅快照、节点哈希、目标域名、成功/失败、出口 IP、总耗时、TLS 握手延迟和上下行字节。点击行查看详情。普通订阅的自动任务统一显示「自动检测」；付费订阅区分周期检测、故障复测、分配验证与手动检测。这里的成功遵循现有探测判定；普通延迟检测接受任意 HTTP 响应状态。

日志仅覆盖实际执行的探测，缓存命中、预算阻止、等待退避及被动业务健康反馈不记录。目的地址只记录域名，错误使用分类提示，不保存响应正文、URL 查询参数或代理凭据。上下行在节点出站流中测量，包含目标 TLS，但不包含所有代理协议开销，不能替代供应商账单。

日志持久化到 state.db，批量写入（通常 1 秒内可见），保留最近 7 天、最多 100,000 条。保留清理在写入时执行；查询不展示超过 7 天的数据。达到容量时淘汰旧记录，不影响单独的探测预算账本。异常退出可能丢失队列中尚未落盘的记录；队列满或写入失败的条数会显示在页面，计数在重启后清零。日志从新版运行后开始生成，不能补录此前的探测。

查询 API：`GET /api/v1/probe-logs`，使用管理员鉴权；参数为 `from`、`to`（RFC3339，起始包含、结束不包含）、`subscription`、`node_hash`、`target_host`、`kind`、`reason`、`success`、`limit`、`cursor`。返回 `items`、`has_more`、`next_cursor` 及保留上限、丢失计数。使用返回的游标翻页，默认 100 条，最多 2,000 条。
