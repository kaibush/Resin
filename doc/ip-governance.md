# Resin IP 治理与活跃账号软门限

Resin 直接依据平台当前可路由节点池分配出口 IP。该功能只在 Resin 内统计和选择，不调用 grok2api 的治理回调，也不要求 grok2api 开启增强设置中的 IP 治理模式。

## 配置

在 Resin 的平台新建或编辑页面设置：

- **启用 Resin 本地 IP 软门限**：开启后对新建粘性租约应用下方门限，并阻止配置的代理旁路规则绕过 Resin 路由。
- **每个出口 IP 的活跃账号软门限**：大于 0 时，低于门限的候选 IP 优先；设为 0 时不应用门限。

粘性身份由 grok2api 经 Resin 代理传入的账号标记区分。相同身份会复用原租约，不重复计数；不同身份各有独立租约。软门限不是硬拒绝：如果当前池中所有 IP 都已达到门限，Resin 仍会把新身份分配到活跃租约数最少的 IP，保证代理请求可以继续。

新建粘性租约始终按活跃租约较少的唯一出口 IP 均衡分配。平台中多个节点若共享同一实际出口 IP，只算一个候选 IP，不会因为重复节点提高该 IP 被选中的权重。选择好 IP 后，Resin 再按平台策略在该 IP 的节点间选路。无粘性请求仍使用平台原有的节点分配策略。

## 计数与租约生命周期

每个活跃租约代表一个 Resin 平台内的粘性身份。计数在新租约选定后增加，在租约删除、替换或到期清理时减少；同一租约的普通续用不会改变计数。选路过程会先短暂预留候选 IP 的名额，再在分配锁外执行节点验证，避免并发新账号都看到相同的空闲 IP，也避免慢验证阻塞其他账号分配。

租约到期后，账号下一次请求会从当时的平台节点池重新选择 IP；过期租约不再占用负载。活跃计数在内存中增量维护，过期账号由按到期时间组织的队列分批清理，不需要为了每次分配枚举所有账号租约或查询整张租约表。

## 性能边界

平台可路由节点按版本缓存为「唯一 IP → 节点」候选快照。普通分配只读取这份快照和各 IP 的原子计数；节点成员关系或出口 IP 变化时才重建快照。重建会遍历当前平台的可路由节点，但不会扫描数据库中的账号或租约表。每次选路只比较当前池的唯一出口 IP 数量，计数更新与租约生命周期维护不依赖账号总量。

跨平台重复出现的同一出口 IP 使用全局活跃租约计数，避免同一真实出口被拆到不同 Resin 平台后各自低估负载。门限按每个平台的配置生效；它始终是软门限，不会因超过门限拒绝业务请求。

## 与 grok2api 的职责

grok2api 继续正常使用 Resin 代理，并为每个需要粘性的账号发送稳定且唯一的粘性标记。账号到节点/IP 的分配、活跃账号计数和软门限均由 Resin 负责。grok2api 原增强设置中的 IP 治理软/严格模式不再参与这一分配流程；其 IP 审计页面保留的是历史观测数据，不是实时租约计数或 Resin 门限的控制面。
