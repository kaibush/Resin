# Resin IP 治理扩展

本 fork 已合入 IP 治理扩展，基于上游提交 `9b8ef8e5cf83071fbac4de29bd7187268b9cff7b`。

## 构建与发布

推送 master 会触发 Governance image 工作流，运行路由、代理与 API 测试后发布 `ghcr.io/kaibush/resin:governance` 和 `governance-<完整提交 SHA>`。生产部署使用提交标签或 digest。

源码已包含扩展，无需再次应用 grok2api 中的补丁。也可在仓库根目录运行 `docker build -t resin:governance .`。

未设置 `RESIN_GOVERNANCE_URL` 时保持原生路由行为。必须先部署支持治理回调的 grok2api，再添加以下环境配置；旧应用没有该端点，提前开启会导致路由拒绝。

## 运行配置

保留 Resin 原有配置、代理令牌与数据卷，增加：

```yaml
environment:
  RESIN_GOVERNANCE_URL: http://grok2api:8000/internal/v1/ip-governance/route
  RESIN_GOVERNANCE_TOKEN: ${RESIN_ADMIN_TOKEN}
```

端口和服务名按部署网络调整。`RESIN_GOVERNANCE_TOKEN` 必须与 grok2api「Resin 对接」里保存的管理员 Token 一致；不是代理 Token。治理端点必须能从 Resin 访问。跨不可信网络时使用 HTTPS。不要把令牌放入 URL。

grok2api 中受管节点的代理地址须指向与 Resin 对接设置相同的主机和端口，并保留 `{account}` 粘性身份模板；节点名称继续与 Resin 平台名称精确匹配。直连、其他代理和无粘性身份的固定/轮换代理不具备此协议，不作为软/严格模式的兜底路径。

升级两端后，在「设置 → 增强设置 → IP 账号治理」刷新状态；保持审计模式配置好采购批次与实际 IP 清单、有效期、固定出口确认及门限，然后保存需要的模式。启用限制前会先同步现有租约，导入已有账号/IP 历史。

## 数据面行为

- 所有受管路由从当前平台的完整可路由视图列举候选，按实际 IP 调用应用端统一准入；不是随机抽到两次失败就认定资源耗尽。
- 应用端在数据库事务中读取最新账号关联集合、模式、采购与隔离规则，按历史累计口径原子登记。多个平台和应用实例共用一份账本。
- Resin 在同一粘性身份的租约更新临界区内请求决策，并复核节点仍可用、实际 IP 相符、准入未过期后提交。到期续建、同 IP 替代节点、故障重选和继承均经过治理。原身份不变。
- 继承在限制模式下重新执行统一准入，不无条件复制父账号的出口；审计模式保留原继承行为。启动恢复的旧租约不能绕过下一次路由检查。
- 限制模式关闭新请求对旧连接的复用，且不能通过 Resin 的目标直连绕过规则；在途流不批量中断。回到审计模式后恢复原连接与旁路策略。
- 限制模式不再让本项目的匿名 IP 探针申请普通 Resin 租约，避免探针被准入拒绝后误将整个平台标为不健康。节点健康由 Resin 原生探测与可路由视图提供；账号定向业务探测仍执行统一准入。
- 回调不可用、IP 漂移、供给过期、隔离或严格容量不足时不发起未经批准的业务连接。应用维护绑定等待任务，不重放原业务请求。

`GET /api/v1/governance` 和 `POST /api/v1/governance/route` 是本扩展新增的管理员接口，不是原生 Resin API。后一个接口只维护身份绑定，不发送业务请求；用于后台迁移、等待重试和业务预检查。

## 一致性与范围

采用**单调的历史准入登记**，不是可过期的临时名额预留：数据库批准的账号/IP 关系在 Resin 写入或连接失败后也保留，并明确记录为「准入」，不伪造为「观察到业务使用」。这避免应用数据库与 Resin 内存之间的两阶段提交，以及超时释放名额后发生迟到写入的超额风险；代价是失败的已批准分配可能消耗历史名额。审计租约观察另行记录。

后台只保存账号组身份，每次执行重新取完整候选与最新数据库规则，不把之前挑选的目标 IP 带入下一次重试。旧平台任务发现账号范围已经变化时变为 obsolete；不会覆盖新平台绑定。

采购清单表示所选平台内这些实际 IP 的购买授权。平台的可路由节点视图负责移除失效路径；如果同一 IP 的不同供给路径有不同购买权限，应在 Resin 使用不同平台划分供给范围，再分别配置批次。供给必须由供应商保证真实出口固定，页面的「已核验且固定」是管理员对该供给事实的确认，不能用一次 IP 探测替代供应商保证。

目前硬隔离为显式管理员配置，覆盖该 IP 的全部平台；没有自动根据风险评分或单次缺思考隔离整 IP。跨批次不自动清理历史登记或解除隔离。

回滚时先在应用切回审计模式，再停用扩展/还原 Resin 镜像。保留数据库中的历史登记、批次变更记录和等待任务；不要通过删除历史满足容量上限。
