# Resin 历史账号 IP 均衡与软门限

在 Resin「平台详情 → 配置」打开 **启用历史账号 IP 均衡**，并设置 **每个出口 IP 的历史账号软门限**。关闭时不记录新的历史，也不执行历史均衡；请求恢复平台原分配策略，已有历史保留。`PREFER_IDLE_IP` 原策略仍按活跃租约择路，与历史均衡开关相互独立。

## 计数和分配

- 同一出口 IP 首次使用一个不同粘性标记，历史计数加 1。
- 同一标记再次使用同一 IP 不重复计数，即使原租约已经过期或删除。
- 同一标记首次使用另一个 IP，该 IP 的计数加 1。
- 租约过期、删除，节点退池以及关闭开关，均不减少历史计数。
- 同一个出口 IP 的记录跨 Resin 平台合并；相同标记跨平台使用相同 IP 仍只算一次。客户端应为不同账号提供不同且稳定的标记。

开启后，需要重新选择出口的粘性绑定从当前平台可路由节点池中选择历史不同账号数最少的唯一出口 IP。多个节点共用出口只算一个 IP；选定 IP 后再按平台策略选节点。已有有效绑定保持粘性，无粘性请求仍按原策略选路。

门限大于 0 时优先使用低于门限的 IP；所有可用 IP 都达到门限时仍选择历史账号最少的 IP，不拒绝请求。门限为 0 表示不设门限，开启开关后仍按历史数均衡。该功能减少账号在少数出口上的集中，不能保证不触发上游账号风控。

## 到期优先复用原 IP

在「平台详情 → 配置 → 租约保持时长」附近打开 **到期优先复用原 IP**（API 字段 `sticky_reuse_ip`，默认 `false`）。它独立于历史账号 IP 均衡，可以只为 grok2api 平台开启。

- 同一平台、同一稳定粘性标记的租约到期后，优先使用最近绑定的出口 IP；租约被后台清理、服务重启后仍可找回。
- 原节点退池但当前平台还有其他可用的同 IP 节点时，继续使用该 IP。验证失败会尝试同出口的其他节点；原 IP 不在当前平台可路由池内时，再按历史均衡或平台原策略重新分配，并覆盖最近绑定。
- 原 IP 复用优先于历史均衡及软门限，即使该 IP 的历史账号数已达到门限，也不会因此换 IP。同账号复用不增加历史数；新账号仍按已配置的策略分配。
- 成功复用后建立一个完整 TTL 的新租约。有效租约上的请求不会延长原到期时间。账号的最近绑定按平台隔离，历史账号计数仍跨平台合并。
- 关闭后停止记录和复用，保留最近绑定；已有有效租约继续保持粘性，到期后按通常策略分配。重新开启时优先采用仍保留的当前租约。新开关开启前已清理的租约无法追溯；仍保留的租约会在下次使用或到期清理时记录。
- 手动删除租约仅移除活跃租约，不清除最近绑定；清零历史计数也不影响最近绑定。删除平台会同时删除该平台的最近绑定。

最近绑定存于 `state.db` 的 `sticky_ips` 表，每个 `(platform_id, account_hash)` **仅一行**，换 IP 使用原行更新。账号使用 32 字节 SHA-256 二进制摘要，IP 使用 4/16 字节二进制值，额外保存一个绑定时间用于防止重启时旧租约缓存覆盖新绑定。表使用 `WITHOUT ROWID`，避免重复的主键索引；不存账号原文、节点副本或每次续租明细。空间随不同账号数增长，不随请求数、续租次数或换 IP 次数增长；要无限期记住不同账号，就必须保留每个账号的一条记录。

请求路径只查询内存账号索引和缓存的 IP → 节点索引，不查询数据库或遍历全部账号；IP 索引仅在平台视图变动时重建。同 IP 复用只做检查，不写最近绑定表。仅首次记录或出口改变时同步持久化一次，探测与数据库写入均不占用全局分配锁。启动时流式加载最近绑定，避免构建第二份完整列表，无定时全表扫描。

配置示例：`PATCH /api/v1/platforms/{id}`，请求体 `{"sticky_reuse_ip": true}`。创建平台时也可设置该字段。

## 页面和接口

「平台详情 → IP 使用」展示当前平台全部可用唯一 IP，包括历史数为 0 的 IP，支持搜索、门限筛选、排序和分页。

页面区分可用 IP 总数、已有历史的 IP、零历史 IP、达到门限的 IP，以及当前有活跃租约的 IP。列表展示每 IP 历史不同账号数、当前活跃账号数、可用节点数、门限与状态。历史和活跃数均跨平台汇总，活跃数只供观察。

- `GET /api/v1/platforms/{id}/ip-history`：上述列表与汇总，分页前应用过滤与排序，默认按历史数降序。
- `DELETE /api/v1/platforms/{id}/ip-history?egress_ip=...`：经管理鉴权后手动清零一个 IP 的全局历史；页面要求确认跨平台影响。不会清除租约，下次使用重新累计。
- 原 `/ip-load` 和 `/leases/ip-count` 继续返回活跃租约数，供既有客户端观察。

## 持久化与升级

历史保存在 `state.db` 的独立表中，以规范化 IP 和粘性标记 SHA-256 摘要为唯一键，不存标记原文。累计记录仅由显式清零删除，重启不会丢失。首次升级用仍保留的、已开启平台的租约建立历史起点；已被旧版本删除的历史无法还原。迁移起点只建立一次，手动清零不会在重启时被旧租约恢复。

## CPU 和并发

请求使用内存去重集合和增量计数；同一标记复用租约只做常数次查询，不扫描账号、租约或历史数据库表。仅首次出现的 IP/标记组合需要一条有唯一索引的持久化插入；重复请求不写历史数据库。持久化失败会返回错误并释放预留名额，避免将未保存的历史当作已完成分配。

新绑定只比较当前平台的唯一出口 IP 数量。IP 到节点的候选视图按版本缓存，成员或出口发生变化才重建。使用蓄水池抽样处理同负载候选，不为每次分配分配整批候选数组。并发选择先预留名额；验证和数据库写入在分配锁外执行，计数提交与释放预留在短锁内完成。

历史只在启动时加载一次，无历史定时全表扫描或到期清理任务。管理页每次只返回一页，打开时每 30 秒刷新，隐藏时不后台轮询。页面汇总只遍历可用 IP 的内存计数，显式清零也不遍历其他 IP 的历史账号。

grok2api 的旧 IP 审计页仍是历史观测页面，不控制 Resin 的分配策略。
